- 2026-09-28 — TTS 503 opaque corrige (task `tts-error-contract`) : cause reelle = **quota ElevenLabs epuise** (upstream `401 {"code":"quota_exceeded"}`) + cle `.env` sans permissions `voices_read/models_read` (`/v1/voices|models` -> 401 -> `[]` silencieux). Le backend jetait tout en `503 "TTS not available for provider"`. Decisions : (1) contrat `TtsSynthesisOutcome` = `{ok:true, audioData} | {ok:false, code, provider, status, detail}` avec codes `QUOTA_EXCEEDED(429) / INVALID_API_KEY(401) / MISSING_API_KEY(401) / VOICE_UNAVAILABLE(400) / UNSUPPORTED_PROVIDER(400) / PROVIDER_UNAVAILABLE(502)` et payload `{statusCode, code, provider, message, detail}` ; textes partagés via `SHARED_TTS_ERROR_MESSAGES` (`libs/shared/constants/messages.ts`). (2) **backend = axios** (regle ecrite dans `stack.md`) : `tts-http.util.ts` (`postForAudio/postForJson/getJson`, timeout 15s, `validateStatus:()=>true`) — attention, axios rend le corps d erreur en Buffer avec `responseType: arraybuffer` : il faut `Buffer.toString("utf8")` sinon la classification lit `{"type":"Buffer","data":[...]}` et rate le quota. (3) **frontend = Angular 20 resources** (regle ecrite dans `stack.md`) : `TtsSynthesisService.synthesize()` est une action `HttpClient` Observable (`firstValueFrom` dans `TtsService`), `fetch` natif reserve au SSE chat ; `formatHttpError` privilégie le `message` serveur -> un seul toast avec la vraie cause. (4) une seule tentative upstream pour quota/cle (`planDefaultRetry`) : l ancien code en lançait 3 par tentative et brulait des credits. (5) le tsconfig backend n a pas `strict` : TS ne rétrécit que par `x.ok === false` (pas `!x.ok`) — à retenir pour les unions. Preuves : backend 192/192, `tsc -p tsconfig.app` FE 0 erreur, curl 400/401/429 avec code+detail. Suites : migrer `fetch` de gemini-live/groq/genkit vers axios ; specs FE en echec (message/ai-config/memory/prompt-tag/user-profile) = refactor http en parallèle (HttpClient non fourni dans leurs TestBed).
